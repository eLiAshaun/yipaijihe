# 一拍迹合 · Trip Journal

> 把收藏夹里的旅行灵感，走成一条**真的走得通**的路线。

粘贴抖音视频、小红书笔记、攻略文字 → 找出里面提到的地点 → 结合你的「旅行人格」筛选 →
生成逐日路线，并在编辑时实时告诉你：**赶不赶得上、哪天闭馆、要不要预约、花多少钱、该带什么**。

抖音精选内容重构黑客松参赛作品。

## 快速开始

**macOS / Linux**

```bash
./run.sh
```

**Windows**：双击 `run.bat`

脚本会自动检查 Python（需要 3.10+）、创建虚拟环境、安装依赖（官方源装不上时自动改用清华镜像）、生成 `.env`，
然后打开浏览器 `http://127.0.0.1:8000`（端口被占用会自动顺延）。首页点 **「先逛逛，不注册」** 就能直接体验全流程。

### 只需要一个 DeepSeek Key

在 `.env` 里填上 `DEEPSEEK_API_KEY=sk-...`，默认使用 **`deepseek-flash`（DeepSeek-V4.1-Flash，能看图）**，一个 Key 打开全部 AI 能力：

| 能力 | 怎么做的 | 不填 Key 时 |
|---|---|---|
| 排行程、旅行搭子对话 | DeepSeek 编排，行程引擎逐条校验时间与地点 | 行程引擎编排；本地助手基于行程、景点库和天气回答 |
| **联网搜索**任意城市 | Exa 语义搜索 / 头条搜索 / Bing / DuckDuckGo 并行找最新攻略，Jina Reader 读攻略全文 → DeepSeek 只根据这些资料归纳地点、**注明出处** → 地理编码校正坐标 | 使用内置景点库（上海） |
| 联网搜索的**后备** | 搜索引擎都不可用时退回 DeepSeek 自身知识（标注「未核实」）；还不行就用内置景点库 | — |
| 对话里查实时信息 | DeepSeek 自己决定要不要搜（营业时间、门票、预约、闭馆），回答带 [1][2] 引用链接 | 提醒出发前确认 |
| **听**视频讲解（抖音 / B 站 / YouTube / 小红书 / 西瓜视频） | yt-dlp 下载（抖音用分享页解析），本地 Whisper 转写（免费、离线，`run.sh` 自动安装），再由 DeepSeek 结合画面字幕改正地名错字 | — |
| **看**视频画面 | 截取关键帧交给 DeepSeek 读字幕、招牌、地标（很多视频只配音乐，地名全在画面上） | 只读视频标题和你粘贴的文案 |

> DeepSeek 的 API 不带联网搜索工具，也不接收音频，所以「搜」和「听」由本项目完成，「读」和「理解」交给 DeepSeek。
> 想换模型：改 `LLM_BASE_URL` / `LLM_MODEL` / `LLM_API_KEY`（OpenAI / 通义 / Kimi / Ollama 都行）。配置了 `DOUBAO_API_KEY` 时联网搜索优先用豆包自带的搜索。

关于本地语音模型：第一次启动会在后台下载 Whisper `small`（约 460MB，huggingface.co 连不上时自动走 hf-mirror.com），
下载完成前视频分析会先看画面和标题，不会卡住。嫌大可以在 `.env` 设 `ASR_MODEL=base`（约 145MB），不需要可以设 `ASR_ENGINE=off`；
有 MiMo Key 时填 `MIMO_API_KEY` 改用云端转写。

`.env` 里写 `your-xxx` 这类占位值等同于没填。AI 服务出错时会自动熔断 3 分钟、改用本地能力，不会让页面卡住。

### 互联网渠道（参照 Agent Reach）

[Agent Reach](https://github.com/Panniantong/agent-reach) 是给 AI Agent 接入各平台的工具箱，它的思路是「只负责选型、安装、体检和路由，直接使用上游工具」。
网站按同样的选型接入了其中不需要登录的渠道，运行时直接调用上游，不依赖 `agent-reach` / `mcporter` 命令：

| 渠道 | 上游 | 在网站里做什么 |
|---|---|---|
| 全网语义搜索 | Exa（`mcp.exa.ai`，免 Key） | 联网搜索的一个来源，结果自带正文摘录；对话里查实时信息 |
| 任意网页 | Jina Reader（`r.jina.ai`，免 Key；Exa web_fetch 作后备） | 读攻略全文（连头条、知乎这类要执行 JS 的页面）；灵感素材里的文章链接 |
| 视频 | yt-dlp | B 站、YouTube、小红书、西瓜视频的下载；抖音分享页解析失败时兜底 |

想给自己的 AI 助手也装上 Agent Reach（开发时用来搜资料、读网页、看视频），参考它的
[安装说明](https://raw.githubusercontent.com/Panniantong/agent-reach/main/docs/install.md)：
`pip install` 之后先运行 `agent-reach install --env=auto` 做只读检查，再用 `agent-reach doctor` 查看各渠道状态。
仓库里旧的 `agent-reach/` 目录是项目早期的本地脚本（抖音 MCP + mcporter），网站已经不再依赖它。

## 我们针对同类产品做了什么

调研了旅行规划类产品（攻略 App、AI 行程助手、收藏夹工具）的常见吐槽，逐条在这里解决：

| 常见痛点 | 一拍迹合的做法 |
|---|---|
| 收藏夹吃灰，灵感散落在抖音、B 站、小红书、公众号、聊天记录里 | **灵感素材**页：链接和文字混着粘。视频（抖音 / B 站 / YouTube / 小红书 / 西瓜）会**听讲解 + 看画面**，每条视频实时显示进行到哪一步、听到了什么、看到了什么；**文章链接**（公众号、知乎、马蜂窝、携程…）读取正文；文字直接识别地名，并附上「原文里那句话」 |
| AI 推荐的地方查不到来源、信息过时 | **联网搜索**最新攻略，每个推荐地点都带**出处链接**；搜不到资料时明确标注「未核实」 |
| AI 行程看着漂亮、实际走不通 | **行程引擎**：按地理聚类分天、天内最短路线、逐站「停留 + 通勤」推算时间，赶不上会标红并写明差几分钟 |
| 夜景排在中午、早市排在下午 | 读取每个景点的**建议时段**：排序时傍晚 / 夜间景点放最后，排时间时等到时段开始，下午空出来自由活动 |
| 到了才发现闭馆 / 要预约 / 末班船没了 | 从景点数据解析**闭馆日、预约、末班时间**；填了出发日期会自动把景点换到开放的那天，并在行前清单里列出待办 |
| 只顾着逛，忘了吃饭 | 跨过饭点自动安排顺路的餐饮点，没有就**预留用餐时段**并一键在高德搜附近餐厅 |
| AI 编造不存在的地点 | 大模型的输出逐条校验：候选列表外的地点直接丢弃，时间排不开的天由引擎重排 |
| 改一处就得整个重来 | 拖拽、上下移、移到另一天、**锁定时间**（订好的餐厅 / 门票不会被自动排时间改动）、撤销 / 重做 |
| 到了现场还要切 App 查路线 | 每个景点一键**导航**（高德，手机上直接唤起 App）；旅行当天顶部显示**下一站**和剩余时间 |
| 问 AI「现在开门吗」，它凭记忆瞎答 | 旅行搭子会**联网查**营业时间、门票、预约，回答附引用；距离、预算等事实由本地按行程计算后交给它 |
| 预算心里没数 | 按景点 / 餐饮消费档位和通勤方式实时估算人均花费，超预算立刻提醒 |
| 一上来就要注册 | **游客模式**直接开始，之后在右上角「设置账号」转正，数据全部保留 |
| 测试题太长 | 8 道题约 2 分钟；也可以**直接选**自己是哪种旅行者 |
| 同一个地方加了两次 | 加入前检查重复，提示它已经在第几天并高亮 |
| 和朋友对不上行程 | 搭子同步 + 人格契合度建议；只读**分享链接**，对方可一键复制成自己的行程 |
| 离线就用不了 | 导出手机日历（`.ics`，提前 30 分钟提醒）、PDF、海报（截图组件已内置）、纯文字 |

## 七个步骤

| 步骤 | 做什么 |
|---|---|
| 01 旅行人格 | 8 道题（单选 / 排序 / 滑块）或直接选择 → 6 种旅行人格，决定节奏与偏好 |
| 02 行程规划 | 城市、出发日期、天数、节奏（悠闲 / 适中 / 紧凑，默认由人格推断）、预算 |
| 03 旅行搭子 | 同步搭子、对比契合度；可以借用 TA 分享的行程 |
| 04 灵感素材 | 粘贴链接与文字，识别出地点 |
| 05 地点筛选 | 地图与列表联动；按人格预选；可补充景点库推荐、手动搜索添加 |
| 06 路线编辑 | 见上表 |
| 07 导出分享 | 海报 PNG · PDF · 日历 `.ics` · 文字 · Markdown · 只读分享链接 |

## 架构

```
app.py                     应用工厂：路由注册、安全头(CSP)、统一 JSON 错误、端口自动顺延、后台预热语音模型
backend/
  config.py                环境配置（占位 Key 视为未配置；默认 DeepSeek deepseek-flash）
  database.py              SQLite 建表 + 种子数据 + 旧数据迁移
  routes/                  auth · mbti · locations · itinerary · video(+jobs) · inspiration · chat · buddy · trips(+weather)
  services/
    planner.py             ★ 行程引擎：分天 / 排序 / 排时间 / 闭馆与预约解析 / 饭点 / 校验大模型输出
    web_search.py          ★ 联网搜索：多搜索源并行 + 相关性过滤 + 大模型归纳（带出处）+ 后备链
    llm_service.py         大模型调用：JSON 模式、思考开关、工具调用（对话联网搜索）、熔断
    asr.py                 语音转写：本地 Whisper（后台下载 / 镜像后备）或 MiMo 云端
    vision.py              看画面：关键帧 / 图文笔记交给多模态模型读字幕与招牌
    video_processor.py     抖音链接 → 下载 → 听 + 看（每一步可单独失败）
    geo.py                 地理编码（Open-Meteo / Photon）+ WGS-84 → GCJ-02 坐标转换
    catalog.py             联网 / 视频发现的地点写入景点库（同名沿用库里数据）
    jobs.py                后台任务与进度（视频分析）
    assistant.py           本地旅行助手：基于行程、景点库、天气计算回答
    inspiration.py         从任意文字里识别地点
    reach.py               互联网渠道（参照 Agent Reach）：Exa 搜索、Jina Reader 读网页、yt-dlp 下载视频
    trips.py               行程仓储（增删改查 / 分享）
frontend/                  无构建步骤：原生 ES Modules + CSS
  js/services/planner.js   ★ 前端行程引擎（与后端规则一致，编辑时实时计算）
  js/services/map.js       高德 / 示意图 双实现
  js/pages/                一页一个模块，按需加载
  vendor/html2canvas.min.js  海报截图（MIT，内置以便离线使用）
tests/
  test_api.py test_features.py test_ai.py test_reach.py   后端（63 项，全部离线：大模型 / 搜索 / 读网页 / 视频用假数据驱动真实代码路径）
  js/planner.test.mjs                       前端行程引擎（22 项）
```

### 设计取舍

- **搜和听自己做，读和想交给大模型**：模型只根据编号资料回答并引用出处；转写错字由画面字幕和景点库纠正；地点名必须在原文 / 画面里出现才采纳，坐标一律走地理编码。
- **每一步都能降级**：搜索源被墙 → 换源 → 模型知识（标注未核实）→ 内置景点库；语音模型没下好 → 先看画面；大模型超时 → 熔断后用本地引擎。
- **两端同一套规则**：后端引擎负责生成，前端引擎负责编辑时的实时校验，阈值（步行 ≤1.3 km、公共交通 ≤9 km、饭点窗口、建议时段解析）保持一致并各自有测试。
- **只用数据里写明的信息**：闭馆、预约、末班、建议时段都从景点数据解析，不臆测；没有坐标的地点如实标为「待定位」，不编造坐标。
- **无构建、无框架**：所有动态文本走 `textContent`，天然免疫 XSS。
- **地图可降级**：高德加载失败即回退到 SVG 示意图，接口一致。

## 部署

仓库自带 `Dockerfile`（gunicorn）和 `render.yaml`：Render 上 **New → Blueprint → 选择本仓库** 即可。

```bash
docker build -t yipaijihe .
docker run -p 8080:8080 -v yipaijihe-data:/data yipaijihe
```

SQLite 和语音模型位于 `/data`，请挂载持久卷。镜像默认包含视频分析组件（`--build-arg VIDEO=0` 可去掉，镜像小约 300MB）。
局域网 / 手机访问本机服务：在 `.env` 设置 `FLASK_HOST=0.0.0.0`。

## 安全说明

- 默认只监听本机、关闭调试模式；密码使用 scrypt（旧哈希登录后自动升级）；接口不回显异常细节
- 搭子同步、视频分析、文字识别需要登录（游客也算）；只有主动开启分享的行程才对搭子可见
- 视频链接仅允许抖音系域名并限制数量；联网搜索只读取搜索结果里的公网网页，跳过内网 / 本机地址（防 SSRF）；分享链接为随机 token，可随时关闭
- 响应带 CSP / `nosniff` / `Referrer-Policy`

## 已知限制

- 内置景点库只有上海；其他城市靠联网搜索（首次约 20–30 秒，之后 6 小时内有缓存，搜到的地点会存进景点库）
- 联网搜索抓取的是公开搜索页面：搜索引擎改版或限流时会自动换源 / 退回模型知识，但结果数量可能变少
- 抖音作品数据来自公开分享页，失败时用 yt-dlp 再试；都不行时只能用你粘贴的分享文案
- B 站 / YouTube 对机房 IP 有风控（412、要求登录），部署在服务器上时可以在 `.env` 的 `YTDLP_COOKIES` 填浏览器导出的 cookies.txt；YouTube 还需要本机有 node / deno
- 小红书图文笔记需要登录才能看全文，读不到时会改用你粘贴的分享文案
- 本地语音转写在 CPU 上运行：1 分钟的视频约 15–30 秒；视频背景音乐很响时准确率会下降
- 通勤为直线距离 ×1.3 的估算（地图可用时路线使用高德真实路网）；天气来自 Open-Meteo，仅覆盖未来 16 天
- 价格为消费档位估算，不含住宿与城际交通
